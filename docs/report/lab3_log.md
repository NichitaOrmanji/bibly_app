# Журнал выполнения ЛР3 — навигация, формы и валидация (Bibly)

Материал для отчёта. Скриншоты — в `screenshots_l3/`.
Проект продолжает ЛР2 (тот же репозиторий, та же история Git).

## План маршрутов

```
/login                         вне shell, без вкладок
/search                        вне shell, открывается push-ем
StatefulShellRoute.indexedStack (AppShell + NavigationBar)
├─ /day                        Мой день
├─ /bible                      список книг
│   └─ :bookId                 главы книги          (push)
│       └─ :chapter            чтение главы         (push; соседние главы — go)
├─ /diary                      Дневник
│   ├─ new                     форма новой записи (перед :id!)
│   ├─ tabernacle              пароль Скинии → go в entries
│   │   └─ entries             Скиния
│   └─ :id                     детали записи
├─ /together                   Вместе
│   └─ :groupId                детали группы
└─ /profile                    Профиль
    └─ edit                    форма профиля
```

## Ход работы

### Шаг 1. Пакет go_router
- `flutter pub add go_router` → в `pubspec.yaml` появилась зависимость `go_router: ^18.1.0`,
  точная версия зафиксирована в `pubspec.lock`.
- Коммит: «L3: добавлен пакет go_router».

### Шаг 2. Модели получают id
- `BibleBook.id` — номер книги в синодальном порядке (1 — Бытие … 43 — От Иоанна … 66 — Откровение).
- `DiaryEntry.id` — записи Дневника 1–7, записи Скинии 101–106 (не пересекаются).
- `ReadingGroup.id` — группы 1–6.
- `MockData.lastReadBookId = 43` — для адреса «Продолжить чтение» `/bible/43/3`.

### Шаг 3. Карта маршрутов: router.dart и MaterialApp.router
- `lib/router.dart`: глобальный `GoRouter` с `initialLocation: '/login'`, у каждого экрана свой адрес.
  Пока карта плоская; вкладки остаются в `MainShell` до шага со `StatefulShellRoute`.
- `main.dart`: `MaterialApp` → `MaterialApp.router(routerConfig: router)`, параметр `home:` удалён.
- Все «леса» ЛР2 (`Navigator.push` + `MaterialPageRoute`) заменены адресами:
  - лупа → `context.push('/search')`;
  - «Продолжить» и пункт «Отрывок из Библии» → `context.push('/bible/43/3')`;
  - Скиния → `context.push('/diary/unlock')`, после пароля `context.go('/diary/tabernacle')`;
  - «Войти» → `context.go('/day')`, «Выйти» → `context.go('/login')`.
- `ChapterScreen` теперь получает `bookId` и `chapter` из адреса `/bible/:bookId/:chapter`
  (`int.parse(state.pathParameters[...]!)` — параметр пути всегда `String`) и сам ищет книгу
  через `firstWhere`. Текст есть только у Ин 3, для других глав — заглушка «загрузится с сервера (ЛР5)».
  Соседние главы — `context.pushReplacement`, чтобы «назад» вела к списку, а не по всем главам.
- Проблема: после перехода на `GoRouter` 6 тестов упали, хотя по одному проходили. Причина —
  `router` глобальный и помнит адрес между тестами. Решение: `setUp(() => router.go('/login'))`.
- Проверка: `flutter analyze` — без замечаний; 10 тестов пройдены.

### Шаг 4. Цепочки «список → детали» с /:id
- Переиспользуемые карточки получили `onTap` (место, оставленное в ЛР2):
  `BookTile` (уже был), `DiaryEntryCard` (новый параметр), `_GroupCard` во «Вместе».
- Новые экраны деталей — каждый получает id из адреса и **сам ищет объект** через
  `firstWhere` (без `extra`):
  - `BookScreen` (`/bible/:bookId`) — сетка глав (`GridView.builder`), последняя
    прочитанная глава подсвечена; нажатие → `push('/bible/43/3')`;
  - `EntryScreen` (`/diary/:id` и `/diary/tabernacle/:id`) — полная запись;
  - `GroupScreen` (`/together/:groupId`) — план, прогресс, участники.
- Порядок маршрутов: фиксированные `/diary/unlock` и `/diary/tabernacle` стоят выше
  переменного `/diary/:id`, иначе «unlock» попал бы в `int.parse` и приложение упало бы.
- Новый тест: адреса `/bible/1`, `/bible/43/3`, `/diary/2`, `/diary/tabernacle/101`,
  `/together/2` открывают правильные объекты. 11 тестов пройдены.

### Шаг 6. Формы с валидацией и вход
- `lib/utils/validators.dart` — все правила в одном месте; каждый validator возвращает
  текст ошибки или `null` (= значение верное). Ошибку красным под полем рисует сам `TextFormField`.
- Все формы — `StatefulWidget`: `GlobalKey<FormState>`, контроллеры в `State`,
  по одному `dispose()` на контроллер; submit: `validate()` → невалидно `return`,
  валидно SnackBar + `pop()`/`go()`.
- **Вход** (`login_screen.dart`): `Form`, e-mail и пароль; после успешной проверки
  `context.go('/day')` — **go, не push**: вход уходит из стека, системная «назад»
  не возвращает на него. Реальной проверки пользователя нет — любые корректные
  данные впускают (ЛР5). Иконка-глаз показывает/скрывает пароль (`setState`).
- **Новая запись** (`/diary/new`, `new_entry_screen.dart`): заголовок, ссылка на стих,
  текст, `DropdownButtonFormField` «Куда сохранить» со своим validator-ом.
  Открывается: FAB в Дневнике (push), FAB в Скинии (`?place=tabernacle`),
  «В дневник» из главы — `go('/diary/new?verse=Ин 3')` (переход в другой раздел).
  После сохранения — SnackBar «Запись «…» сохранена в Дневник/Скинию» и `pop()`;
  список не растёт — это контракт ЛР3, состояние появится в ЛР4.
- **Пароль Скинии** (`/diary/unlock`): 4–6 цифр, `digitsOnly` + `LengthLimitingTextInputFormatter(6)`,
  цифровая клавиатура, `obscureText`; успех → `context.go('/diary/tabernacle')`.
- **Редактировать профиль** (`/profile/edit`, кнопка-карандаш в «Профиле»): имя, e-mail,
  телефон (`phone` + `digitsOnly`, до 9 цифр), «О себе» (`maxLength: 120`).

### Шаг 7. Обратная связь: SnackBar и диалоги подтверждения
- Правило: только сообщаем — SnackBar; просим решение — диалог с `await`.
- `lib/widgets/confirm_dialog.dart` — `showConfirmDialog(...)`, переиспользуется трижды:
  - диалог закрывается через **`dialogCtx`** (контекст самого диалога): под вложенными
    навигаторами вкладок `pop(context)` экрана закрыл бы экран, а не диалог;
  - результат — **`ok == true`**, а не `ok!`: диалог, закрытый нажатием мимо, возвращает `null`;
  - после `await` контекст используется только при **`context.mounted`**.
- Деструктивные действия с подтверждением:
  - «Выйти» в Профиле → «Выйти из аккаунта?» → `context.go('/login')`;
  - корзина в записи → «Удалить запись?» → SnackBar «Запись «…» удалена» + `pop()`;
  - «Покинуть группу» → подтверждение → SnackBar + `pop()`.
  Реальное удаление/выход из группы — в ЛР4 (контракт ЛР3: подтверждение + SnackBar).
- SnackBar без другого видимого эффекта: «Сохранено» в формах, «Помолюсь» в ленте,
  «Закладка: От Иоанна 3» в главе.
- Новый тест: после входа `router.canPop() == false` (вход ушёл из стека); «Выйти» →
  «Отмена» оставляет в профиле, «Да, выйти» ведёт на вход. 16 тестов пройдены.

### Шаг 8. Проверка полного потока на эмуляторе и скриншоты (`screenshots_l3/`)
Поток, который показывается на защите, пройден целиком:

- 5 вкладок shell-а: `20_tab_day` … `24_tab_profile`; прокрутка вкладки сохраняется (`01`), детали внутри вкладки (`02`);
- список → детали с разными id: `30_chain_book_1` (/bible/1) → `31_chain_chapter_1_1` (/bible/1/1, заглушка),

  пустые поля → 4 ошибки, включая «В книге «От Иоанна» глав: 21» (`41`); заполнено → SnackBar (`42`);
  пароль Скинии «12ab» → буквы отфильтрованы, «От 4 до 6 цифр» (`43`) → «1234» → Скиния (`35`),
  «назад» из Скинии ведёт в Дневник (экран пароля ушёл из стека); профиль: e-mail «nikita»,

- обратная связь: диалог удаления записи (`50`) → SnackBar «Запись … удалена» (`51`);
  диалог «Покинуть группу?» (`52`); «Выйти из аккаунта?» (`53`) → «Да, выйти» → экран входа без вкладок (`13`).
- Замечание: `adb shell input text` не умеет вводить кириллицу, поэтому в скриншоте формы
  заголовок и текст записи набраны транслитом («Nochnye voprosy»).
